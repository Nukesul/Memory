# Memoris 2.0, фаза 2: дизайн-система и навигация

## Состояние после фазы 1 (на 26.11.2026)

**Безопасность.**
- Вход только по приглашению, строгий RLS, закрытое хранилище фото. Всё проверено на живой базе.
- В базе 0 аккаунтов: админ ещё не зарегистрировался, поэтому вход в браузере на живом сайте пока не проверен.

**Код.**
- React 19, Vite и Supabase на месте.
- `app-context.jsx` (~470 строк) — один контекст на всё: сессия, данные, чат, пуши, тема, язык и т. д.
- `styles.css` (~1400 строк) состоит из слоёв v1…v8, дописанных один за другим.
- 89 толстых рамок (`2–2.5px solid var(--ink)`) и 64 «наклейки»-тени (`Npx Npx 0 var(--ink)`).
- Три шрифта: Unbounded, Onest, Caveat.

**Навигация.**
- Шесть вкладок: Класс · Люди · Альбом · Чат · Игры · Кабинет.
- Язык и тема лежат в шапке на каждом экране.
- На главной 6–7 блоков: вопрос дня, чек-лист, объявления, «для тебя», плитки, герой.

**Данные.**
- Ориентированы на профили: фото лежат массивом в `profiles.data`, таблицы постов нет.
- Чат — одна таблица `messages`: `to_id = null` — это класс, иначе личка.

**Фото.** Бакет приватный, показ идёт через подписанные ссылки на 7 дней.

## Решение по фото (на согласование)

**Предлагаю:** вернуть **публичное чтение** бакета `photos`, а запись оставить строгой (только в свою папку, админ может удалить любое). Новые файлы получают случайные имена по 128 бит.

**Последствия.**
- Фото откроет любой, у кого есть точная ссылка, но список файлов получить нельзя, а угадать имя невозможно.
- Взамен фото открываются сразу, кэшируются CDN и браузером, их можно скачать, и не нужен отдельный запрос на подписи.
- Это упрощает ленту, истории и фото в чате в фазах 3–6.
- Личные сообщения, аккаунты, приглашения и админ-данные остаются закрытыми, как сейчас.

## Дизайн-система

| Токен | Светлая | Тёмная | Где используется |
|---|---|---|---|
| `--bg` | #F6F6FA | #0F0E1A | фон приложения |
| `--surface` | #FFFFFF | #17162A | карточки, листы |
| `--surface-2` | #EFEFF6 | #201F36 | поля, подложки |
| `--line` | #E3E3EE | #2C2B45 | тонкие разделители 1px |
| `--text` / `--muted` | #16152B / #66658A | #F1F0FA / #A3A2BF | текст |
| `--accent` | #4B3FD9 | #8F85FF | кнопки, активная вкладка, ссылки |
| `--heart` | #FF4D7E | #FF6B93 | лайки, непрочитанное |
| `--ring` | sun #FFC531 → heart → grape #8A6BFF | то же | кольцо историй, бренд 2J |
| семантика | ok #1F9D6B · warn #B97F00 · danger #D93B31 | светлее | статусы, ошибки |

- **Шрифты.** Onest для всего интерфейса. Unbounded только для логотипа и заголовков в «Воспоминаниях». Caveat только для рукописного: автографы и заметки.
- **Шкала текста:** 13 / 15 / 16 (основной) / 18 / 22 / 28. Интерлиньяж 1.5 у текста и 1.2 у заголовков. Поля ввода не меньше 16px, чтобы iPhone не увеличивал страницу.
- **Отступы:** 4 · 8 · 12 · 16 · 20 · 24 · 32 · 48.
- **Скругления:** 10 (поля), 12 (кнопки), 16 (карточки), 24 (листы), круг (аватары).
- **Тени:** только две — у меню и листов. Карточки без теней, рамка 1px.
- **Движение:** 150–220 мс. При `prefers-reduced-motion` всё выключается.
- **Касания:** не меньше 44px.
- **Компоненты** (`src/components/ui/`): Button (primary/secondary/ghost/danger), IconButton, Field, Avatar (размеры, точка «в сети», кольцо историй), Segmented/Tabs, Badge, Skeleton, EmptyState, PageHeader, Sheet (на основе текущего BottomSheet), Toast.

## Навигация

**Телефон:** нижняя панель из пяти пунктов с учётом безопасной зоны.

| Пункт | Маршрут | Что там в фазе 2 |
|---|---|---|
| Главная | `#/` | объявления, новые фото класса (из уже загруженных), кто в сети, вход в вопрос дня |
| Поиск | `#/explore` | поиск одноклассников по имени и стране, сетка всех фото |
| Создать (+) | лист | только рабочие действия: добавить фото в профиль, заметка на стену, ответ на вопрос дня. Посты добавятся в фазе 3 |
| Сообщения | `#/chat` | текущий чат с бейджем непрочитанного |
| Профиль | `#/me` | мой профиль и «Редактировать». Настройки открываются через ⚙ |

**Верхняя панель на телефоне:** логотип слева, справа «Воспоминания».

**Компьютер (от 1024px):** боковая панель с теми же пунктами, плюс «Воспоминания» и «Настройки». Контент шириной до 640px, у сообщений и поиска — шире.

**Воспоминания** `#/memories`: альбом, стена, ежегодник, автографы, капсула, вопрос дня, номинации, игры, объявления, помощь.

**Настройки** `#/settings`:
- аккаунт;
- **смена пароля** (новая функция);
- онлайн-статус, уведомления, установка приложения;
- язык и тема (убираются из шапки);
- выход;
- админка (только для админа).

**Старые адреса** (`#/people`, `#/gallery`, `#/play`, `#/book` и т. д.) продолжают работать.

- **Стили:**

- **Контекст:** из `app-context` выносится только UI-часть (тема, язык, тосты, листы). Полный разбор отложен до фаз 3–6, когда появятся новые данные.

## База данных

- Новых таблиц нет.
- Одна миграция (если решение по фото принято): `photos` снова `public = true`, политики записи без изменений. Откат — одна строка `update storage.buckets set public = false`.
- Клиент перестаёт подписывать ссылки, но умеет читать оба формата адресов. Существующие фото не трогаются.

## Проверка фазы 2

- **Playwright, матрица:**
  - ширины 360 · 375 · 390 · 430 · 768 · 1024 · 1280;
  - светлая и тёмная тема;
  - RU / EN / JA.
- **Проверяется:**
  - нет горизонтальной прокрутки;
  - нижняя панель не перекрывает контент;
  - каждый пункт меню ведёт на рабочую страницу;
  - старые адреса открываются;
  - фокус виден с клавиатуры;
  - нет ошибок в консоли;
  - скриншоты каждой страницы просмотрены.
- **Живой сайт:**
  - после выкладки проверяю из базы через `pg_net`, что GitHub Pages отдаёт новую сборку;
  - API проверяю тестовыми аккаунтами, которые потом удаляю.
- **Что я не могу проверить отсюда:** интерфейс живого сайта в настоящем браузере под реальным аккаунтом. Это проверяете вы по короткому чек-листу или открываете сайт в Chrome на компьютере с расширением Claude, уже войдя в аккаунт.
